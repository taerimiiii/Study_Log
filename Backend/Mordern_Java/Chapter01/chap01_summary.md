## 2. 스트림 (Stream) 처리

- 자바 8 에서 스트림 API가 추가되었다.
- 스트림 패키지에 정의된 `Stream<T>`는 `T` 형식으로 구성된 일련의 항목(데이터의 흐름)을 의미한다.

    - synchronized 같은 복잡한 스레드 제어 코드 없이도, 스트림 API 내부적으로 멀티 코어를 활용하여 **공짜 병렬성**을 얻을 수 있다.

## 3. 동작 파라미터화로 메서드에 코드 전달하기

- 코드의 일부(동작)를 다른 메서드의 인수로 넘겨주는 기능. 이를 **동작 파라미터화(Behavior Parameterization)** 라고 부른다.

❓

**왜 필요한가?**

</aside>

- 자바 8은 해결책으로 정렬 조건(비교 로직)이 담긴 **메서드 자체를 인수로 전달**할 수 있게 되었다.

*(💡 동작 파라미터화의 다양한 활용은 2장, 3장에서 다룰 예정)*

## 4. 병렬성과 공유 가변 데이터

- 자바 8은 병렬 처리가 용이하다. 스트림을 이용하면 병렬 처리를 쉽게 할 수 있다. 하지만 이를 안전하게 수행하려면 지켜야 할 규칙이 있다.
- 멀티스레드 환경에서 안전하게 동시 실행하려면, **공유된 가변 데이터(Shared Mutable Data)에 접근하지 않아야 한다.**
    
    즉, 상태를 바꾸지 않는 **순수 함수(Pure function)**, **부작용 없는 함수(Side-effect-free function)** 를 작성해야 한다. *(→ 18, 19장에서 상세 학습)*
    
- 일급 시민과 이급 시민
    - 일급 시민: 변수에 할당할 수 있고, 메서드의 인수로 전달할 수 있으며, 반환값으로 사용할 수 있는 값. (예: `int`, `String`, 객체)
    - 이급 시민: 구조체나 메서드처럼 직접 전달할 수 없는 요소들.
    
    → 자바 8은 메서드와 람다를 '일급 시민'으로 격상시켜 함수형 프로그래밍의 기반을 마련했다.
    

## 5. 메서드와 람다를 일급 시민으로

자바 8에서는 메서드를 값처럼 전달할 수 있도록 두 가지 새로운 문법을 제공한다.

### 5.1. 메서드 참조 (Method Reference `::`)

- 기존에 정의되어 있는 메서드를 직접 전달할 때 사용한다.

```java
// [자바 8 이전] 익명 클래스 사용 (숨겨진 파일 필터링)
File[] hiddenFiles = new File(".").listFiles(new FileFilter() {
    public boolean accept(File file){
        return file.isHidden(); // 숨겨진 파일인지 확인하는 메서드 호출
    }
});

// [자바 8 이후] 메서드 참조 사용
File[] hiddenFiles = new File(".").listFiles(File::isHidden);
```

### 5.2. 람다 (Lambda) : 익명 함수

- 이름이 없는 함수로, 짧고 간결하게 코드를 넘겨줄 때 사용한다.
- 예시: `(int x) -> x + 1` (x라는 인수를 받아서 x+1을 반환)

#### 💻 코드 넘겨주기 예제 (사과 필터링)

특정 항목을 선택해서 반환하는 동작을 '필터(Filter)'라고 한다. `inventory`에 담긴 사과 중 **녹색 사과**만 필터링 해보자.

```java
// 1. 조건을 검사하는 메서드 정의
public static boolean isGreenApple(Apple apple){
    return "green".equals(apple.getColor());
}

// 2. 메서드 참조를 통해 필터 메서드에 조건(동작) 전달
List<Apple> greenApples = filterApples(inventory, Apple::isGreenApple);

// 3. 람다를 사용하면 메서드 정의조차 생략 가능 (가장 간결함)
List<Apple> greenApples = filterApples(inventory, (Apple a) -> "green".equals(a.getColor()));
```

## 6. 스트림과 멀티스레딩

대부분의 자바 애플리케이션은 컬렉션(List, Map 등)을 사용한다. 스트림 API는 컬렉션 처리의 패러다임을 바꿨다.

- **외부 반복 (External Iteration)**
    - for-each 루프처럼 개발자가 직접 컬렉션의 요소를 하나씩 꺼내와서 반복(루프)을 지시하는 방식. (자바 8 이전의 방식) = 컬렉션
- **내부 반복 (Internal Iteration)**
    - 무엇을 할지만(필터링, 추출 등) 지정하면, 데이터 처리 로직을 스트림 라이브러리 내부에서 알아서 처리해주는 방식. 병렬 처리를 라이브러리가 알아서 최적화해준다. = 스트림

### 데이터 처리의 핵심 동작 (멀티스레딩 활용)

스트림은 큰 데이터를 여러 CPU 코어로 나누어(Fork) 동시에 아래의 작업들을 수행하고 결과를 하나로 합친다(Join).

- 데이터 필터링 (Filtering)
    
    → 특정 조건에 맞는 데이터만 추려냄 (예: 무게가 150g 이상인 사과만 선택)
    
- 데이터 추출 (Extracting / Mapping)
    
    → 데이터의 특정 필드만 뽑아내거나 변환함 (예: 사과 객체에서 사과의 '무게' 값만 추출)
    
- 데이터 그룹화 (Grouping)
    
    → 특정 기준에 따라 데이터를 분류함 (예: 사과를 '색상별'로 묶음)
    

## 7. 디폴트 메서드 (Default Method)

- 기존 자바에서는 인터페이스(Interface)에 새로운 메서드를 추가하면, 해당 인터페이스를 구현(implements)하던 모든 클래스에서 에러가 발생하여 일일이 구현을 추가해줘야 했다.
- 그.래.서. 자바8은 `default` 키워드를 사용해 인터페이스 내부에도 구현이 있는(바디가 있는) 메서드를 작성할 수 있도록 해 주었다.
- 이에 따라, 기존 코드를 전혀 건드리지 않고도 라이브러리(인터페이스)를 유연하게 발전시킬 수 있다.

*(💡 다중 상속 시 발생할 수 있는 '다이아몬드 상속 문제'는 9장에서 설명)*

## 8. 함수형 프로그래밍의 유용한 아이디어

자바 8은 함수형 언어의 장점을 대거 흡수했다.

- `Optional<T>` 클래스 (→ 11장)
    
    NullPointer 예외를 피할 수 있도록 돕는 컨테이너 객체
    
- 구조적 패턴 매칭 기법 (→ 19장)
    
    복잡한 if-then-else나 switch를 깔끔하게 처리
    
- 스칼라(Scala) 프로그래밍 언어 (→ 20장)
    
    함수형 프로그래밍의 아이디어를 자바가 어떻게 차용했는지 비교
